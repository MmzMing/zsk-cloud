# 文档图片与视频封面上传流程设计

---

## 一、设计原则

- 图片与文章/视频信息分离上传，先图后文
- 富文本中只存引用（URL/Token），不存二进制
- 审核后置：图片上传时不审核，内容提交后统一审核
- 临时文件独立管理，自动过期清理

## 三、阶段一：图片上传（临时存储）

### 3.1 前端行为

1. 用户在编辑器中粘贴/选择/拖拽图片
2. 前端对图片进行客户端预处理：
   - 文件类型校验（限制 jpg/png/webp）
   - 文件大小校验（单张限制）
   - 图片压缩（可选，减少传输体积）
3. 前端发起图片上传请求
4. 上传过程中显示 loading 占位图
5. 上传成功后，用返回的临时 Token 替换占位图

### 3.2 后端行为

1. 接收图片文件流
2. 安全校验：
   - 文件非空校验
   - MIME 类型校验
   - 文件魔数校验（防止伪造扩展名）
   - 文件大小校验
3. 生成文件哈希（用于秒传去重）
4. 生成唯一存储路径，上传至对象存储（私有 Bucket）
5. 写入临时文件记录：
   - 临时 Token（随机字符串，非自增 ID）
   - 用户 ID（绑定上传者）
   - 文件元信息（名称、大小、类型、存储路径）
   - 创建时间、过期时间（24 小时后）
6. 返回临时 Token 给前端

### 3.3 输出

- 前端获得临时 Token
- 对象存储中已有文件（私有，不可直接访问）
- 临时文件表中已有记录（带过期时间）

---

## 四、阶段二：用户编辑内容

### 4.1 前端行为

1. 编辑器中图片通过临时 Token 获取预签名 URL 进行回显
2. 用户可继续上传更多图片
3. 用户可删除编辑器中的图片（仅前端移除，不触发后端删除）
4. 用户编写文章/视频标题、正文、描述等信息
5. 选择封面图（从已上传图片中选择，或单独上传）

### 4.2 状态说明

- 此阶段所有图片均为临时状态
- 用户可随时关闭页面，临时文件将在 24 小时后自动清理
- 草稿自动保存时只保存文本内容和临时 Token 列表

---

## 五、阶段三：提交文章/视频

### 5.1 前端行为

1. 用户点击"发布"或"提交审核"
2. 前端组装提交数据：
   - 文章/视频基本信息（标题、正文、分类、标签等）
   - 正文内容（包含图片临时 Token）
   - 封面图临时 Token（如有）
3. 发起提交请求

### 5.2 后端行为

1. 接收文章/视频信息 + 临时 Token 列表
2. 基础校验：
   - 文本内容非空、长度校验
   - 分类、标签有效性校验
3. 图片 Token 校验：
   - 提取正文和封面中的所有临时 Token
   - 校验每个 Token 是否存在
   - 校验每个 Token 是否属于当前用户（防越权）
   - 校验每个 Token 是否已过期
4. 临时文件转正式文件：
   - 将校验通过的临时文件记录迁移至正式文件表
   - 生成正式文件 ID
   - 状态标记为"待审核"
5. 替换正文内容：
   - 将正文中的临时 Token 替换为正式文件访问 URL
6. 保存文章/视频信息：
   - 写入文章/视频主表
   - 建立文章/视频与文件的关联关系（关联表记录文件类型：正文图片/封面）
7. 触发异步审核任务（MQ）：
   - 文本内容审核（敏感词、政治内容等）
   - 图片内容审核（涉黄、涉暴、广告等，调用云厂商审核服务）
8. 返回提交成功结果

### 5.3 输出

- 文章/视频已入库
- 文件已转入正式表，状态"待审核"
- 关联关系已建立
- 审核任务已投递至消息队列

---

## 六、阶段四：内容审核（异步）

### 6.1 审核流程

1. 审核服务消费 MQ 消息
2. 并行执行：
   - 文本审核：敏感词过滤、政治内容检测
   - 图片审核：批量调用云厂商内容安全 API
3. 汇总审核结果

### 6.2 审核结果处理

| 结果 | 文章/视频状态 | 文件状态 | 处理方式 |
|------|-------------|---------|---------|
| 全部通过 | 已发布/已通过 | 正常 | 正常展示 |
| 文本违规 | 审核不通过 | 正常 | 返回拒绝原因，允许修改后重新提交 |
| 图片违规 | 审核不通过 | 违规 | 标记违规图片，返回拒绝原因 |
| 部分图片违规 | 审核不通过 | 违规图片标记违规 | 提示替换违规图片后重新提交 |

---

## 七、阶段五：临时文件清理（定时任务）

### 7.1 清理时机

- 定时任务每日执行
- 扫描临时文件表中已过期的记录（创建时间超过 24 小时）

### 7.2 清理行为

1. 查询所有已过期的临时文件记录
2. 从对象存储中删除对应的物理文件
3. 从临时文件表中删除记录

### 7.3 说明

- 已被转正式的临时记录不会进入清理范围（转正式时已从临时表删除）
- 用户放弃编辑、关闭页面的孤儿文件由此机制自动回收

---

## 八、视频封面特殊场景

### 8.1 用户手动上传封面

- 流程与文档图片完全一致
- 封面上传后同样返回临时 Token
- 提交视频时一并携带封面 Token

### 8.2 系统自动截取封面

1. 用户上传视频文件
2. 后端异步处理视频（文件处理任务）：
   - 视频转码
   - 使用视频截取工具提取指定时间帧作为封面
   - 将封面图上传至对象存储
   - 封面图直接写入正式文件表（无需临时表，因为是系统生成）
3. 用户提交视频时，封面文件 ID 已就绪

## 九、安全设计要点

| 风险点 | 防护措施 |
|--------|---------|
| 水平越权（盗用他人文件） | Token 绑定用户 ID，提交时严格校验归属 |
| Token 遍历攻击 | 使用随机字符串 Token，非自增数字 ID |
| 文件伪造上传 | MIME + 魔数双重校验 |
| 超大文件攻击 | 前端 + 后端双重大小限制 |
| 临时文件堆积 | TTL + 定时清理机制 |
| 内容违规传播 | 审核后置 + 先审后发 |

## 十一、关键状态流转

### 11.1 文件状态流转

```
上传成功（临时表）
    │
    ▼
┌─────────┐    提交文章/视频      ┌─────────┐    审核通过      ┌─────────┐
│  临时   │ ------------------> │  待审核  │ -------------> │  正常   │
└─────────┘                     └─────────┘                └─────────┘
    │                               │
    │ 24h 过期                      │ 审核不通过
    ▼                               ▼
┌─────────┐                     ┌─────────┐
│  已清理  │                     │  违规   │
└─────────┘                     └─────────┘
```

### 11.2 文章/视频状态流转

```
草稿（前端状态，未提交）
    │
    ▼
┌─────────┐    审核通过      ┌─────────┐
│  待审核  │ -------------> │  已发布  │
└─────────┘                └─────────┘
    │
    │ 审核不通过
    ▼
┌─────────┐    修改后重新提交   ┌─────────┐
│ 审核失败 │ ----------------> │  待审核  │
└─────────┘                   └─────────┘
```

## 十二、异常处理

| 异常场景 | 处理方式 |
|---------|---------|
| 图片上传失败 | 前端提示重试，保留编辑器其他内容 |
| Token 过期 | 后端返回具体过期 Token，前端提示重新上传对应图片 |
| Token 归属错误 | 后端拒绝提交，返回越权错误 |
| 审核服务异常 | MQ 重试，超过次数进入死信队列，人工介入 |
| 对象存储上传失败 | 后端返回上传失败，前端可重试 |
| 用户编辑中途关闭页面 | 临时文件 24h 后自动清理，无数据残留 |
